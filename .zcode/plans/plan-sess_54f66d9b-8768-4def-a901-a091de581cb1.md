# Служба FreeC Tier: Wintun выносим из UI-процесса

## Цель и архитектура

UI-процесс перестаёт требовать права администратора. Wintun-адаптеры переезжают в системную службу (LocalSystem), общение — по именованному пайпу. Ключевой факт из исследования: **валидация входящих пакетов требует Steam-личности отправителя** (`packet.incoming(config, &sender_id, local)`, sender приходит только из транспорта) — поэтому роутинг и весь Steam-движок остаются в UI-процессе, а служба становится stateless «насосом»: открыть/закрыть адаптер, гонять IPv4-пакеты. Конфиги сетей службе не нужны.

```
[UI: freec-tier.exe, asInvoker, без UAC]          [Служба: freec-service.exe, LocalSystem]
  Steam-движок + роутинг + подписи                  ITaskService-пайп-сервер (1 клиент)
  transport ↔ Steam P2P          ← именованный пайп →  Wintun-адаптеры (map Uuid→session)
  packet.incoming/outgoing валидация                  netsh (адрес+MTU), без UAC
```

Следствия: тумблеры «Пропускать UAC»/«Автозапуск» и вся машинерия задач планировщика **удаляются** (исчезает главный поведенческий FP-триггер — создание задачи); автозапуск UI — через HKCU Run-ключ (манифест asInvoker уже стоит); служба стартует сама через SCM (auto-start). UI-автозапуск и служба не требуют UAC; UAC остаётся один раз — при установке службы.

## Новые крейты

**1. `client/ipc` (freec-ipc)** — чистый кодек протокола пайпа, без Windows-зависимостей (core остаётся чистым по политике). Фрейм: `[u32 len LE][u8 type][payload]`, len ≤ 64К.
- Клиент→Служба: `Hello{protocol}`, `OpenAdapter{network: Uuid, local_ip: Ipv4Addr}`, `CloseAdapter{network}`, `Packet{network, bytes}`.
- Служба→Клиент: `Welcome`, `AdapterOpened{network}`, `Packet{network, bytes}`, `Error{text}`.
- Unit-тесты кодека на roundtrip и границы размеров.

**2. `client/service` (bin freec-service)** — depends: freec-ipc, freec-core (типы), windows-service, wintun.
- Служба SCM: имя «FreeC Tier Service», start=auto, восстановление при сбое. Флаги: `--service` (SCM-режим), `--console` (отладка в консоли), `--install`/`--uninstall` (саморегистрация, пишет SID вызвавшего пользователя в `HKLM\SOFTWARE\FreeC Tier\ServiceUser`).
- Пайп-сервер `\\.\pipe\FreeCTier\v1`: один клиент, `PIPE_REJECT_REMOTE_CLIENTS`, DACL из SDDL `SY` + `BA` + SID из реестра (ответ на вопрос о безопасности).
- Adapter manager: переезд логики `adapter.rs` (wintun load по пути службы, open/create по имени `FreeC-{uuid12}`, netsh адрес+MTU, `start_session`); отключение клиента → закрыть все адаптеры; подключение нового → чистое состояние. Пакеты: поток чтения каждой сессии → пайп; пакеты из пайпа → `inject` в нужную сессию. Служба **ничего не валидирует** — доверию к единственному подключенному клиенту соответствует DACL.

## Изменения в существующем

**3. `client/runtime`** — `adapter.rs` заменяется пайп-фасадом с тем же интерфейсом для движка:
- `PipeClient` (OnceLock, инициализируется в `start()`): фоновый поток подключения с retry, демультиплексирование пакетов по сетям в bounded-очереди (1024, переполнение → drop), outbound-очередь.
- `Adapter::open(config, local)` → синхронный RPC `OpenAdapter` + ожидание ack (5с таймаут) — `SetAdapter`/restore в движке не меняются; `receive()` = `try_recv` из очереди сети; `inject()` = в очередь; `Drop` = `CloseAdapter`.
- Реконнект: при разрыве — переподключение и **пере-регистрация всех открытых адаптеров**, движок продолжает считать адаптеры открытыми (Snapshot-флаг не мигает).
- Служба не отвечает → ошибка с текстом «Служба FreeC Tier не запущена — переустановите её в настройках».
- `freec-runtime` CLI получает службу автоматически (тот же фасад), работает без ручной элевации.

**4. `client/gui/src-tauri`**
- **Удалить**: `is_elevated`, `relaunch_helper`, `--freec-relaunch`, `apply_task`/`schtasks`, команды `set_skip_uac`/`set_autostart`, AV-warning диалог и его проводку в тестах, тумблеры skip-uac/autostart из настроек.
- **Добавить**: `service_status` (установлена/запущена — через SCM API), `install_service` / `uninstall_service` (ShellExecuteW runas на `freec-service.exe --install/--uninstall` — один UAC); автозапуск UI — тумблер «Запускать при входе в Windows» через HKCU Run-ключ (winreg).
- `ensure_webview2` остаётся, но без runas-обёртки: бутстраппер Microsoft сам поднимет UAC при установке рантайма.

**5. Установщик и сборка**
- NSIS hooks (`installerHooks` в Tauri): POSTINSTALL — регистрация+запуск службы (сохранение SID), PREUNINSTALL — стоп+удаление. `build.ps1`/`release.mjs`: сборка `-p freec-service`, staging `freec-service.exe` в install dir и NSIS resources (wintun.dll уже стадируется).

**6. Документация**: `architecture.md` (секция службы вместо рукописной элевации), `testing.md` (матрица: рестарт службы при открытых адаптерах, стоп службы, два ПК), `README` («Требования»: служба ставится установщиком; антивирусная секция упрощается — задача планировщика исчезла), `AGENTS.md`.

## Порядок реализации (фазы)

- **A**: крейт `freec-ipc` (кодек+тесты) и `freec-service` (SCM, пайп-сервер, адаптеры, `--console`/`--install`). Проверка вручную через `--console`.
- **B**: пайп-фасад в `freec-runtime` + реконнект; src-tauri: удаление task/elevation-кода, service-команды, автозапуск через Run-ключ; настройки UI.
- **C**: NSIS hooks, staging в build.ps1/release.mjs, docs/README/AGENTS.md, правки Playwright (настройки без старых тумблеров + карточка службы).
- **D**: живая проверка: установка из NSIS, два ПК, рестарт службы при активной сети.

## Проверки и риски

- `cargo test` (новые тесты кодека), fmt, clippy (0 warnings), Playwright — на каждой фазе.
- Пропускная способность пайпа с запасом покрывает игровые трафики (кадр ≤ 1300 Б, батчи не нужны в v1; при необходимости — батчинг позже).
- Риск: доверие пайп-клиенту. Митигируется DACL (один пользователь) + тот факт, что такой же пользователь и так контролирует Steam-сессию. Валидация трафика не ослабляется — она остаётся в UI.
- Риск: служба под LocalSystem — code review поверхности: никаких команд shell, только wintun+netsh+пайп.
- Live-проверку элевации/службы делаем поэтапно на машине (UAC появится только на шаге install).
